# Battle Spirits 線上卡牌遊戲（地基版 / 開發中）

一個以「標準賽（Standard）／永恆賽（Eternal，舊稱大師賽 Master）／無制限（自由對戰）」三種賽制為
基礎打造的 Battle Spirits 線上對戰系統：規則引擎、卡片資料庫、卡組編輯器、單機對電腦（AI）、
本機雙人（同螢幕輪流）、以及可自架的 WebSocket 連線對戰伺服器。

**這是「地基」版本，不是完整上線版本。** 請詳讀下面「目前的限制」再使用/擴充。

## 目前的限制（開始使用前務必先看）

1. **卡片資料混合了示範卡池與真實官方卡片。**
   `shared/data/cards.json` 裡 `DEMO-`/`BS-DEMO-` 開頭的是系統示範卡池（卡名／效果文字都是原創
   占位內容），`26RBS02-` 開頭的**117張是真實官方現行標準賽彈「[26RBS02]幻惑の翔風」的完整
   資料**（card_no／稀有度／卡名／費用／屬性色／種類／系統(家族)／BP／bpLevels／效果文字／
   卡圖／blockIcon，全部是官方原文），已經併入對戰引擎可以直接使用，驗證過能組出合法的40張
   標準賽牌組。這個開發環境的網路政策幾乎擋掉所有外部網站，沒辦法自動爬取官網，所以流程是：
   使用者手動存檔／截圖官網頁面 → 我解析成 JSON → 用 `tools/scrape-card-detail.mjs`（**要在
   使用者自己的電腦上跑**，這個 repo 執行環境連不到 battlespirits.com）補上 bp/效果文字/卡圖 →
   用 `tools/merge-real-set.mjs` 併入 `cards.json`。要收錄更多真實系列，重複同樣流程即可：
   ```bash
   cd battlespirits/tools
   npm install
   node scrape-card-detail.mjs <系列代碼>   # 在自己電腦上跑，補齊 bp/text/image
   # 把更新後的 shared/data/real/<代碼>.json 傳回來
   node merge-real-set.mjs <系列代碼>        # 併入 shared/data/cards.json（這裡執行就好）
   ```
   `shared/data/official-reference.json` 是另一份系列/商品層級的真實參考資料（283筆真實系列/
   商品代碼與名稱、342個真實系統/家族名稱、真實稀有度代碼等）。
2. **官方規則書已核對過，並修正了幾個先前的錯誤假設**（使用者提供了《總合規則》《地板規則》
   《官方規則手冊[STANDARD]》《官方規則手冊[ETERNAL]》四份PDF，2026-07-26 核對）：
   - **契約卡是主卡組40張的一部分**，不是額外的第41張——這是先前一個實際的規則錯誤，已修正
     （`format.js`／`game.js`／`cardDatabase.js`／`starters.json`）。契約卡指定為「開局公開」
     時，起始手牌變成「抽3張＋公開這1張＝一樣4張」，不是「抽4張後再多塞1張」；一副卡組只能
     收錄同一種契約卡，最多3張（跟一般卡片同樣的張數限制，不是只能1張）。契約卡還有一個尚未
     實作的能力：**因對手效果離場時可變成場上的「魂狀態」**而不進墓地，這塊還沒做。
   - **標準賽／永恆賽的合法性判定依據是卡片的「區塊圖示」（`blockIcon`）**，不是系列發售日期：
     區塊圖示是英文字母的卡片才能在標準賽用，且要落在該字母對應的官方輪替期間內（目前唯一
     公告的是「A」：2026/4/1～2027/3/31）；數字或沒有區塊圖示＝僅永恆賽可用。已修正
     `cardDatabase.js`（見 `sets.json` 的 `standardRotation.blockWindows`）；沒有 `blockIcon`
     資料的示範卡池目前仍退回舊有的「依系列發售日期」簡化判斷。
   - **BP/核心（能量）升級機制**：確認是全部靈魂卡＋據點卡的通用機制（不是特定系列限定），
     `effectiveBp()` 已經改成優先讀 `bpLevels` 門檻表。但規則書也指出目前簡化沒做到的地方：
     能量數量其實是「當前值可增可減」（自己的主要階段可自由搬動，次數不限），不是只能單調
     疊加；若場上卡片的能量數量低於Lv1門檻會直接消滅；BP+/BP-效果是動態疊加在「當前Lv的BP」
     上、Lv一變動就要重算，不是算完凍結。這幾點目前引擎都還沒做（`instance.cores` 目前只能
     用 `attachCore` 增加、不能減少），是已知的架構落差。
   - **據點（Nexus）不能攻擊/阻擋、不參與BP戰鬥**——這點原本的假設是對的，不需要修正。
   - **終極靈魂卡（究極）最低Lv是3**（不是1），召喚時要立刻放置能量達到Lv3；場上的終極靈魂卡
     規則上被視為跟一般靈魂卡不同種類，不會被「以靈魂卡為對象」的效果選中。目前引擎的究極卡
     沒有 `bpLevels`／Lv系統，這兩點還沒實作（低優先，因為目前收錄的真實卡片裡還沒有究極卡）。
   - **煌臨（Kourin）**：確認「不算召喚」正確，但「消耗核心」的說法不精確——正確規則是移動
     每人限定唯一一份的「靈魂能量」（不是任意能量），且疊放對象要滿足的是卡片各自指定的
     「煌臨條件」（不是寫死的「同家族」）。目前引擎仍是簡化版（固定核心費用＋寫死家族比對），
     這塊還沒照官方規則重寫。
   - **軽減コスト（費用減免標誌）**：確認是完全獨立的機制（自己場上有同色標誌可折抵費用，
     可折抵到不能超額支付），資料裡目前只原樣記錄圖示顏色（`costAlleviationColor`），引擎
     完全還沒實作這個折抵計算。
   - **U觸發**判定邏輯（對手牌庫頂費用比自己低才算命中）確認正確，不需要修改。
   詳細的規則書原文引用與頁碼，保留在對話紀錄裡，之後要繼續補這些機制可以再挖出來對照。
3. **合作卡（collab）目前只有 1 組虛構示範聯名**（`DEMO-COLLAB-01`，「銀河守護隊」），
   刻意用假的 IP 名稱，不代表任何真實作品的合作卡。要收錄真正的官方合作卡，一樣是往
   `cards.json` / `sets.json` 加資料即可，資料結構已經支援 `collab` / `collabSeries` 欄位。
4. **禁限卡表是從公開規則摘要整理，未逐字核對官方最新的禁止・限制卡公告**
   （`shared/data/banlist.json`），輪替日期判斷已改用官方真正依據的區塊圖示（見上）。
5. **規則引擎其餘的簡化**（詳見 `shared/engine/game.js` 開頭註解，煌臨/究極/U觸發的規則核對
   結果見上）：
   - 核心（core／能量）不分顏色符號，卡片的 `costSymbols` 欄位目前只作顯示用，尚未強制驗證
     顏色需求；軽減コスト費用減免機制也還沒實作（見上）。
   - Flash 關鍵字卡片可以隨時由持有者打出，沒有完整模擬優先權／stack 的介入時機窗口。
   - Bond（左右靈脈區）等進階機制尚未實作。
   - 爆發（Burst）機制採用「覆蓋設置、事件觸發後可發動」的現行機制精神，但沒有做到完整的
     連鎖／優先權判定。
6. **已實作的進階系統**：轉醒（Awakening，卡片正反面自動翻轉）、煌臨（Kourin，疊放召喚，簡化版）、
   究極＋U觸發（Ultimate + U-Trigger）、契約（Contract，40張主卡組的一部分，可選擇開局公開1張）。
   詳見 `shared/engine/game.js` 開頭註解與 `shared/data/cards.json` 的 `DEMO-035`〜`DEMO-040`。
7. **AI 是簡單的規則式 AI**（`shared/engine/ai.js`），不是搜尋樹或機率計算，強度有限，會嘗試打出
   究極卡（含犧牲場上卡片湊條件），但不會主動使用煌臨。
8. **プロデューサーレター vol.21** 的內容目前查不到（搜尋只索引到 vol.12），尚未反映在規則裡；
   若你有連結或截圖內容，直接更新對應的 `shared/data/*.json` 或 `shared/engine/rules.js` 即可。

## 專案結構

```
battlespirits/
  shared/                共用程式碼，client 和 server 都直接 import 同一份，規則只寫一次
    engine/
      rules.js           規則常數（起始核心數、回合步驟…）
      cardDatabase.js    卡片資料索引＋賽制合法性判斷
      format.js          賽制定義（Standard/Eternal/Unlimited）與卡組合法性驗證
      game.js            對戰核心邏輯（權威版本，server 和本機對戰都用它）
      ai.js              簡易規則式 AI
    data/
      cards.json         卡片資料庫（示範資料，見上方限制說明）
      sets.json           系列/彈清單與標準賽輪替設定
      banlist.json        禁止・制限卡表（Standard / Eternal 各自獨立）
      starters.json        現行可用預組（示範版）
      official-reference.json  真實官方參考資料（系列/家族/稀有度代碼，見上方限制說明第1點）
      real/
        26RBS02.json        真實卡片資料（117張，缺bp/效果文字，見上方限制說明第1點）
  tools/                 在自己電腦上跑的資料抓取小工具（不是雲端沙盒用的）
    scrape-card-detail.mjs  補齊 shared/data/real/*.json 裡 bp/效果文字/卡圖的抓取腳本
  server/                自架用 WebSocket 連線對戰伺服器（Node.js）
    src/index.js
    scripts/simulate.mjs  開發用自我測試（跑一整場 AI vs AI 模擬對局）
  client/                瀏覽器前端（純 ES modules，不需要建置工具）
    index.html
    css/style.css
    js/
      dataLoader.js      載入卡片資料、建立資料庫
      deckStore.js        「我的卡組」本機儲存（localStorage）
      cardsUI.js / cardView.js   卡片資料庫瀏覽/搜尋
      deckUI.js            卡組編輯器（含合法性檢查、預組匯入）
      playUI.js            對戰畫面（單機AI／本機雙人／連線對戰共用同一套UI）
      netClient.js         連線對戰用的 WebSocket client 包裝
      app.js               entry point
```

## 怎麼玩（本機／單機）

不需要任何建置工具，直接用靜態伺服器開啟整個 repo 即可：

```bash
cd Yu-gi-oh
python3 -m http.server 8000
# 瀏覽器開 http://localhost:8000/battlespirits/client/index.html
```

1. 「卡片資料庫」分頁：瀏覽/搜尋示範卡池（可勾選只看合作卡、或顯示轉醒背面卡）。
2. 「卡組編輯」分頁：新增卡組、選賽制（標準/永恆/無制限）、從現行預組匯入、逐張調整張數，
   會即時顯示是否合法（40 張下限、同名卡最多 3 張、賽制輪替與禁限表）；契約卡是獨立欄位
   （不算入 40 張），到「卡片資料庫」找契約卡點「設為契約卡」指定。
3. 「對戰」分頁：
   - 🤖 **單機對電腦**：選你的卡組，對手用示範預組之一。試試看「示範預組 E：轉醒・煌臨・
     究極」可以體驗全部四個進階系統（開局手牌會直接有契約卡）。
   - 👥 **本機雙人**：兩人輪流操作同一台裝置（雙方場面都顯示，不做遮蔽，適合面對面）。
   - 🌐 **連線對戰**：見下方「連線對戰」說明。

對戰畫面裡，主要步驟手牌若該卡有「煌臨」能力會出現「煌臨」按鈕，點下去後點選自己場上的
目標卡片即可疊放；究極卡跟精靈一樣有「打出」按鈕（召喚條件不符時 playCard 會直接跳出錯誤
訊息），只有召喚條件是「犧牲場上卡片」的究極卡才會改顯示「召喚（需犧牲卡片）」按鈕，點下去
選好要犧牲的張數後按「確認召喚」；究極卡若帶【U觸發】，攻擊時畫面會出現黃色的 U觸發結果
提示（棄了對手哪張牌、有沒有命中）；轉醒不需要手動操作，條件成立時場上卡片會自動翻面並
標示「已轉醒」。

## 連線對戰（需要自架伺服器）

連線對戰需要你自己啟動 `battlespirits/server`：

```bash
cd Yu-gi-oh/battlespirits/server
npm install
npm start          # 預設監聽 port 8080，可用 PORT=xxxx npm start 改埠號
```

伺服器是**權威端**：所有規則判定（卡組合法性、出牌、攻擊、攔截、爆發…）都在伺服器上用
`shared/engine` 執行，client 只是把操作送過去、畫出伺服器回傳的個人化狀態（會正確隱藏對手
手牌內容，只露出張數）。

前端「連線對戰」分頁填入伺服器的 WebSocket 位址（同機測試用 `ws://localhost:8080`；
部署到雲端主機的話，改成你的網址，例如 `wss://your-domain.com`），一人「建立房間」拿到房號，
另一人輸入房號「加入房間」，兩人到齊自動開局。

若要部署到公開網路：這只是一個普通的 Node.js WebSocket process，可以直接丟到任何支援
Node.js 的主機（VPS、Render、Fly.io、Railway…）上跑 `npm start`；記得開對外的 port，並在
前端網址欄填正確的 `wss://`（有 TLS 的話用 wss，不然用 ws）。

## 開發／測試

```bash
cd battlespirits/server
npm install
npm run simulate     # 載入資料、驗證所有預組合法性、跑一場 AI vs AI 模擬對局，確認引擎沒有炸掉
```

這份「地基」已經過的驗證（用 Playwright 實際操作瀏覽器測試，非純肉眼檢查，若要正式上線建議
再找真人多玩幾局）：
- 6 副示範預組（含合作卡預組、進階系統預組）都通過合法性檢查（40 張主卡組、張數上限、契約卡
  獨立於主卡組之外）。
- AI vs AI 模擬對局可以正常跑完、分出勝負，多次重跑沒有出現無限迴圈或例外；轉醒／煌臨／究極
  召喚條件（含犧牲、BP門檻兩種類型）／U觸發（含命中與不命中兩種情境）都有對應的自動化測試
  （`server/scripts/simulate.mjs`）覆蓋，包含手動觸發與真實對局中自然觸發兩種情境。
- 瀏覽器端完整跑過：卡組編輯→匯入預組→開局→出牌（含負擔不起會正確灰掉）→推進步驟→攻擊→
  對手攔截決策，多回合下來沒有 console 錯誤；契約卡開局直接進手牌並顯示標籤；轉醒背面卡
  預設從卡片資料庫隱藏（可勾選顯示，但不能加入卡組）；煌臨與究極（含犧牲型與條件型兩種）的
  互動皆已在真實瀏覽器中操作驗證成功。這個過程中抓到並修正了一個真的 bug：AI 攻擊時如果
  人類玩家要決定攔不攔截，回應完之後 AI 的回合會卡住不動——已修正為回應完會繼續讓 AI 跑下去
  （處理下一個攻擊者，或推進到下一步驟）。
- 連線對戰：兩個獨立瀏覽器分別建房/加入房，狀態（回合、步驟、雙方手牌張數、場面）正確同步，
  出牌動作即時反映到對手畫面。

## 下一步可以做的擴充方向

- 用真正的官方現行卡表／預組取代示範資料（見上方「目前的限制」）。
- 補齊顏色符號（costSymbols）的強制驗證、Bond／Brave 進化機制、更完整的效果腳本系統
  （目前 magic 卡與部分關鍵字效果是用簡化規則手動實作，還沒有通用的效果直譯引擎）。
- 更強的 AI（例如簡單的 minimax / 手牌價值評估）。
- 帳號系統、對戰紀錄、排位配對（目前連線對戰是純房號配對，沒有帳號概念）。
