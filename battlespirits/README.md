# Battle Spirits 線上卡牌遊戲（地基版 / 開發中）

一個以「標準賽（Standard）／永恆賽（Eternal，舊稱大師賽 Master）／無制限（自由對戰）」三種賽制為
基礎打造的 Battle Spirits 線上對戰系統：規則引擎、卡片資料庫、卡組編輯器、單機對電腦（AI）、
本機雙人（同螢幕輪流）、以及可自架的 WebSocket 連線對戰伺服器。

**這是「地基」版本，不是完整上線版本。** 請詳讀下面「目前的限制」再使用/擴充。

2. **官方規則書已核對過，先前的錯誤假設與已知落差都已修正**（使用者提供了《總合規則》
   《地板規則》《官方規則手冊[STANDARD]》《官方規則手冊[ETERNAL]》四份PDF，2026-07-26 核對，
   同一批次校正）：
   - **契約卡是主卡組40張的一部分**，不是額外的第41張。契約卡指定為「開局公開」時，起始手牌

     卡，最多3張（跟一般卡片同樣的張數限制）。契約卡**因對手效果離場時會變成場上的「魂狀態」**
     而不進棄卻區（`Game._destroy`），但目前沒有任何效果腳本可以把魂狀態的卡復活。
   - **標準賽／永恆賽的合法性判定依據是卡片的「區塊圖示」（`blockIcon`）**，不是系列發售日期：
     區塊圖示是英文字母的卡片才能在標準賽用，且要落在該字母對應的官方輪替期間內（目前唯一
     公告的是「A」：2026/4/1～2027/3/31）；數字或沒有區塊圖示＝僅永恆賽可用（`cardDatabase.js`，
     見 `sets.json` 的 `standardRotation.blockWindows`）；沒有 `blockIcon` 資料的示範卡池目前
     仍退回舊有的「依系列發售日期」簡化判斷。
   - **BP/能量升級機制**：`effectiveBp()` 優先讀 `bpLevels` 門檻表。能量數量是「當前值可增可減」
     （自己的主要階段可自由搬動，次數不限），已用 `attachCore`（貼上）／`detachCore`（移回
     預備區）／`moveCoreBetweenField`（場上卡片互相搬動）三個方法實作，都限定在自己的
     core／main／main2 步驟才能用；若因此讓能量數量低於「維持最低Lv所需的能量數量」，卡片會
     直接消滅（`_vanishIfBelowMinLevel`）。召喚/配置時，付完費用後也會自動從預備區放置能量
     達到最低Lv門檻（一般卡Lv1，終極靈魂卡Lv3，見 `_minCoresRequired`）。**還沒做的部分**：
     BP+/BP-效果動態疊加在「當前Lv的BP」上、Lv變動就重算——這需要有BP+/-效果腳本才能測試，
     目前引擎沒有任何卡片帶這種效果，等未來有通用的效果腳本系統再一併處理。
   - **據點（Nexus）不能攻擊/阻擋、不參與BP戰鬥**——這點原本的假設是對的，不需要修正。
   - **終極靈魂卡（究極）最低Lv是3**（不是1），召喚時已改成自動放置能量達到Lv3（前提是卡片
     資料有 `bpLevels`；目前的示範究極卡 DEMO-038/DEMO-040 還沒有這份資料，所以這兩張示範卡
     暫時視為最低需求0，等實際收錄真實究極卡時會自動套用Lv3規則，不用改程式碼）。「場上的
     終極靈魂卡不會被以靈魂卡為對象的效果選中」這點需要通用的效果目標篩選系統才能實作，
     引擎目前沒有這套系統，仍是落差。
   - **煌臨（Kourin）**：不是「付費」，是移動玩家的1點靈魂能量（簡化成消耗1點預備區能量，
     移到疊放後的卡片身上當額外核心；官方規則的「移到指定特定場所」因為沒有逐卡資料，先
     用這個預設行為），疊放對象要滿足的條件改成通用的 `card.kourin.condition` 系統
     （`{type:'family'|'bpAtLeast', value, text}`），沒有這個欄位時退回舊資料格式
     `targetFamily`。若疊放後能量數量不足以維持新卡片最低Lv，煌臨直接失敗（不是完成後才
     消滅）。官方規則中煌臨元卡片的「煌臨中」效果會持續繼承，這裡仍簡化為只記錄疊放歷史
     （`kourinStack`），還沒有完整的條件式效果繼承系統，是還沒做的部分。
   - **軽減コスト（費用減免標誌）**：已實作 `_costAlleviationAmount`——自己場上如果有跟卡片
     「減輕標誌」同色的標誌，召喚/配置/使用費用會強制折抵。目前資料只記錄減輕標誌的顏色
     （`costAlleviationColor`），沒有記錄實際張數，先固定折抵1點；「6色任一色」／「究極」
     專用／「神」專用這幾種特殊減輕標誌還沒有對應資料，暫不支援。
   - **U觸發**判定邏輯（對手牌庫頂費用比自己低才算命中）確認正確，不需要修改。
   詳細的規則書原文引用與頁碼，保留在對話紀錄裡，之後要繼續補這些機制可以再挖出來對照。
   **UI 說明**：卡組編輯器／對戰畫面目前只有「貼能量」（`attachCore`）有按鈕（核心步驟點選
   場上卡片），`detachCore`／`moveCoreBetweenField` 這兩個新方法引擎已經支援、伺服器動作也
   已經註冊（`detach-core`／`move-core`），但還沒有對應的畫面操作介面，要透過這兩個方法搬動
   能量目前只能直接呼叫 API／引擎方法。
3. **合作卡（collab）目前只有 1 組虛構示範聯名**（`DEMO-COLLAB-01`，「銀河守護隊」），
   刻意用假的 IP 名稱，不代表任何真實作品的合作卡。要收錄真正的官方合作卡，一樣是往
   `cards.json` / `sets.json` 加資料即可，資料結構已經支援 `collab` / `collabSeries` 欄位。
4. **禁限卡表是從公開規則摘要整理，未逐字核對官方最新的禁止・限制卡公告**
   （`shared/data/banlist.json`），輪替日期判斷已改用官方真正依據的區塊圖示（見上）。
5. **規則引擎其餘的簡化**（詳見 `shared/engine/game.js` 開頭註解，煌臨/究極/U觸發/軽減コスト
   的規則核對結果見上）：
   - 核心（core／能量）不分顏色符號，卡片的 `costSymbols` 欄位目前只作顯示用，尚未強制驗證
     顏色需求（軽減コスト費用減免機制已實作，見上，這是不同的兩件事：costSymbols 是「召喚時
     至少要付出這些顏色的能量」，還沒做；軽減コスト是「場上有同色標誌可以折抵費用」，已做）。
   - Flash 關鍵字卡片可以隨時由持有者打出，沒有完整模擬優先權／stack 的介入時機窗口。
   - Bond（左右靈脈區）等進階機制尚未實作。
   - 爆發（Burst）機制採用「覆蓋設置、事件觸發後可發動」的現行機制精神，但沒有做到完整的
     連鎖／優先權判定。
6. **已實作的進階系統**：轉醒（Awakening，卡片正反面自動翻轉）、煌臨（Kourin，疊放召喚，簡化版）、
   究極＋U觸發（Ultimate + U-Trigger）、契約（Contract，40張主卡組的一部分，可選擇開局公開1張）。
   詳見 `shared/engine/game.js` 開頭註解與 `shared/data/cards.json` 的 `DEMO-035`〜`DEMO-040`。
7. **AI 是簡單的規則式 AI**（`shared/engine/ai.js`），不是搜尋樹或機率計算，強度有限，會嘗試打出
   究極卡（含犧牲場上卡片湊條件），但不會主動使用煌臨。
8. **プロデューサーレター vol.21** 的內容目前查不到（搜尋只索引到 vol.12），尚未反映在規則裡；
   若你有連結或截圖內容，直接更新對應的 `shared/data/*.json` 或 `shared/engine/rules.js` 即可。

```
  server/                自架用 WebSocket 連線對戰伺服器（Node.js）
    src/index.js
    scripts/simulate.mjs  開發用自我測試（跑一整場 AI vs AI 模擬對局）
  client/                瀏覽器前端（純 ES modules，不需要建置工具）
    index.html
    css/style.css
    js/
      dataLoader.js      載入卡片資料、建立資料庫
      deckStore.js        「我的卡組」本機儲存（localStorage）

      app.js               entry point
```

## 怎麼玩（本機／單機）

不需要任何建置工具，直接用靜態伺服器開啟整個 repo 即可：

```bash
cd Yu-gi-oh
python3 -m http.server 8000
# 瀏覽器開 http://localhost:8000/battlespirits/client/index.html
```

1. 「卡片資料庫」分頁：瀏覽/搜尋示範卡池（可勾選只看合作卡、或顯示轉醒背面卡）。
2. 「卡組編輯」分頁：新增卡組、選賽制（標準/永恆/無制限）、從現行預組匯入、逐張調整張數，
   會即時顯示是否合法（40 張下限、同名卡最多 3 張、賽制輪替與禁限表）；契約卡是獨立欄位
   （不算入 40 張），到「卡片資料庫」找契約卡點「設為契約卡」指定。
3. 「對戰」分頁：
   - 🤖 **單機對電腦**：選你的卡組，對手用示範預組之一。試試看「示範預組 E：轉醒・煌臨・
     究極」可以體驗全部四個進階系統（開局手牌會直接有契約卡）。
   - 👥 **本機雙人**：兩人輪流操作同一台裝置（雙方場面都顯示，不做遮蔽，適合面對面）。
   - 🌐 **連線對戰**：見下方「連線對戰」說明。

對戰畫面裡，主要步驟手牌若該卡有「煌臨」能力會出現「煌臨」按鈕，點下去後點選自己場上的
目標卡片即可疊放；究極卡跟精靈一樣有「打出」按鈕（召喚條件不符時 playCard 會直接跳出錯誤
訊息），只有召喚條件是「犧牲場上卡片」的究極卡才會改顯示「召喚（需犧牲卡片）」按鈕，點下去
選好要犧牲的張數後按「確認召喚」；究極卡若帶【U觸發】，攻擊時畫面會出現黃色的 U觸發結果
提示（棄了對手哪張牌、有沒有命中）；轉醒不需要手動操作，條件成立時場上卡片會自動翻面並
標示「已轉醒」。

## 連線對戰（需要自架伺服器）

連線對戰需要你自己啟動 `battlespirits/server`：

```bash
cd Yu-gi-oh/battlespirits/server
npm install
npm start          # 預設監聽 port 8080，可用 PORT=xxxx npm start 改埠號
```

伺服器是**權威端**：所有規則判定（卡組合法性、出牌、攻擊、攔截、爆發…）都在伺服器上用
`shared/engine` 執行，client 只是把操作送過去、畫出伺服器回傳的個人化狀態（會正確隱藏對手
手牌內容，只露出張數）。

前端「連線對戰」分頁填入伺服器的 WebSocket 位址（同機測試用 `ws://localhost:8080`；
部署到雲端主機的話，改成你的網址，例如 `wss://your-domain.com`），一人「建立房間」拿到房號，
另一人輸入房號「加入房間」，兩人到齊自動開局。

若要部署到公開網路：這只是一個普通的 Node.js WebSocket process，可以直接丟到任何支援
Node.js 的主機（VPS、Render、Fly.io、Railway…）上跑 `npm start`；記得開對外的 port，並在
前端網址欄填正確的 `wss://`（有 TLS 的話用 wss，不然用 ws）。

## 開發／測試

```bash
cd battlespirits/server
npm install
npm run simulate     # 載入資料、驗證所有預組合法性、跑一場 AI vs AI 模擬對局，確認引擎沒有炸掉
```

這份「地基」已經過的驗證（用 Playwright 實際操作瀏覽器測試，非純肉眼檢查，若要正式上線建議
再找真人多玩幾局）：
- 6 副示範預組（含合作卡預組、進階系統預組）都通過合法性檢查（40 張主卡組、張數上限、契約卡
  獨立於主卡組之外）。
- AI vs AI 模擬對局可以正常跑完、分出勝負，多次重跑沒有出現無限迴圈或例外；轉醒／煌臨／究極
  召喚條件（含犧牲、BP門檻兩種類型）／U觸發（含命中與不命中兩種情境）都有對應的自動化測試
  （`server/scripts/simulate.mjs`）覆蓋，包含手動觸發與真實對局中自然觸發兩種情境。
- 瀏覽器端完整跑過：卡組編輯→匯入預組→開局→出牌（含負擔不起會正確灰掉）→推進步驟→攻擊→
  對手攔截決策，多回合下來沒有 console 錯誤；契約卡開局直接進手牌並顯示標籤；轉醒背面卡
  預設從卡片資料庫隱藏（可勾選顯示，但不能加入卡組）；煌臨與究極（含犧牲型與條件型兩種）的
  互動皆已在真實瀏覽器中操作驗證成功。這個過程中抓到並修正了一個真的 bug：AI 攻擊時如果
  人類玩家要決定攔不攔截，回應完之後 AI 的回合會卡住不動——已修正為回應完會繼續讓 AI 跑下去
  （處理下一個攻擊者，或推進到下一步驟）。
- 連線對戰：兩個獨立瀏覽器分別建房/加入房，狀態（回合、步驟、雙方手牌張數、場面）正確同步，
  出牌動作即時反映到對手畫面。
